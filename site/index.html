The core loop

intentionally simple

Query. Group. Diagnose. Remediate.

01

Query Loki for recent logs across every app in your fleet.

02

Group noisy log lines into a small set of coherent incidents.

03

Ask codex exec to explain likely bugs, misconfigurations, and improvements — with each repo's expected-logs doc as context.

04

Cluster near-duplicates into persistent issues so known noise never alerts twice.

05

Associate each incident with its configured GitHub repository.

06

In an isolated clone, let Codex prepare a minimal fix and regression tests.

07

Enforce patch policy, run validation, and optionally open a pull request.

Containment protocols

Add, amend, or decommission targets from the browser. Validated like the config file, persisted in the state store, live within one poll cycle.

Silence noise — durably

Silence one fingerprint, a whole semantic group, or commit a service-scoped regex pattern that suppresses future variants too. Every entry keeps an editable triage note, and anything can be restored.

Codex-assisted triage

Codex clusters unassigned anomalies into semantic groups and proposes silence patterns — showing live blast radius before you commit. Nothing is ever auto-applied.

Sees outside containment

Errors matching no configured target surface as unassigned anomalies, and a server-side container picker spends your Loki budget only where you're looking.

The dashboard is unauthenticated and can modify configuration. Keep it on a trusted LAN — never expose it to the public internet.

New · Issue memory

One issue. One PR. No re-filing.

Remediation dedups on the logical issue, not the exact log fingerprint. Codex clusters near-duplicate anomalies into one persistent issue, remediates a single representative per run, and holds fire while a PR is open — or for a cooldown after it merges.

Open-PR suppression

An issue whose PR is still open is never re-filed — and after merge or close, a 7-day cooldown (configurable) keeps it quiet.

Cheap by design

Known fingerprints short-circuit from the store; a Codex call is spent only when a genuinely new anomaly class appears. Any Codex error falls back to per-fingerprint dedup.

Expected-logs context

Point a target at a repo doc of deliberate warnings and startup chatter — the Monitor hands it to Codex so benign patterns are never mistaken for anomalies.

Replay captured incidents

guiltyspark replay re-runs a captured incident against a local checkout — evaluate patches safely before ever granting push.

Progressive autonomy

You decide how far it goes.

Every target starts in observe. Promote it only after you trust the diagnosis. It never pushes code unless a target is explicitly configured in draft-pr or pr mode.

Step 1

observe

Detect and diagnose only. Nothing is cloned, nothing is changed.

Step 2

fix

Clone, edit, enforce policy, and validate in isolation — but never push.

Step 3

draft-pr

Run the same checks, then push a GuiltySpark branch and open a draft PR.

Step 4

pr

The same checks, then a review-ready pull request. Final authorization stays yours.

Built for trust

The agent never holds the keys.

GitHub App auth

Install a GitHub App scoped to just your target repos. GuiltySpark mints short-lived installation tokens for its own Git operations — Codex never receives credentials. Personal tokens remain a fallback.

Policy-fenced patches

Per-target allowed paths, max changed files, and required test commands. Fixes happen in short-lived isolated clones and must pass validation before any push.

No API key required

Runs on a ChatGPT-authenticated Codex session — your ChatGPT Pro covers usage instead of a separately billed OpenAI key.

Findings you can pipe

Emits JSONL findings you can tail, ship, or wire into a generic webhook — plus an email when it opens a PR.

Runs on a Raspberry Pi

Native linux/arm64 image, semantic releases to GHCR, Portainer-friendly deployment. Any always-on host you already own.

Yours to run & audit

Apache-2.0, self-hosted, no vendor telemetry. The whole loop runs on infrastructure you control.
